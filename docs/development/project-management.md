# Project Management

DecentDB uses **Hamstik** as its application lifecycle management (ALM) system.

## Roadmap and backlog

All roadmap items, backlog work, bugs, sprints, and acceptance criteria live in
the Hamstik project:

**[sph / DDB — DecentDB](https://hamstik.com/t/sph/projects/DDB)**

Use that project as the source of truth for:

- what is planned, in progress, or done;
- scope, priorities, and acceptance criteria;
- assignments and sprint planning;
- design detail and attachments migrated from retired design specs.

GitHub issues are not the primary backlog. Create or update a Hamstik work item
for planned work; use GitHub for repository-level collaboration where
appropriate.

## Design documents

Architecture decisions remain in the ADRs under `design/adr/`, and user/API
documentation remains under `docs/`.

Retired roadmap and WIN-style specs are indexed in
[`design/HISTORY.md`](https://github.com/sphildreth/decentdb/blob/main/design/HISTORY.md)
with their last commit SHAs, superseding DDB items, and attachment locations.

Do not create a new roadmap or WIN-style spec document as the backlog. Create or
update a DDB work item instead.
